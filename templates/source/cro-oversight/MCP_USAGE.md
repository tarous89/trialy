# ChatGPT / MCP implementation workflow — CRO Oversight 1.2.1

1. **Discover & pin.** Call `read_app_template_guidance(resource:"authoring")` and `usage` to the full `nextOffset`; call `read_app_design`; `list_app_templates`, then `read_app_template` for `life.cro-oversight@1.2.1`. Confirm version+digest; never use a stale plugin-bundled renderer.
2. **Inspect existing workspace and access.** Resolve saved app/reusable data types and current project before proposing six tables. Use platform account identity; **do not** create an app auth/account schema. Verify source column restrictions and current table write permissions. Any provider name is business data only.
3. **Review schemas.** Prepare/apply only authorized tables, fields and record-ID relationships using existing platform review. Recommended names / types are in `schema.example.json`; logical-to-real mappings are in `schema_mapping.example.json`; all real field names/types/schema versions must be retrieved from the workspace. `projectId` is scalar text containing an authorized engagement record UUID; the preview's fictional project IDs never become real.
4. **Configure.** Pass `heading`, `tableMap` of approved typeId/fields/writableFields, `layoutProfile` string, `pageSize`, optional asOf and no `demoLabel`. Source must retain `templateLayoutSchema` first-line declaration and the app's distinctive six screens.
5. **Preview & review.** Verify 0/populated/long/restricted datasets; compare sponsor-verified vs CRO-reported, and correct KPI direction. Save the app using one stable requestKey and exact expectedVersion/manifest; confirm saved identity. A lost save response requires receipt reconciliation, never another app create.
6. **Layout.** Click the settings gear (`tracker:layout`) on the saved custom app. Host `prepare_tool_layout` with `customLayout`, current component ID and expectedVersion; drag rows/screens and review/confirm. Only heading/layoutProfile may change. Reopen and verify order/hidden fields persist without source changes; keep app/data permissions unchanged. Screen hiding is not security.
7. **Record edits.** `records.read` with authorized bindings and bounded pagination; `records.propose` prepares exact create/update changes with expectedVersion; the trusted outer review commits them. Duplicate opens an editable new record with its own ID only after trusted commit; Delete sets archived=true with explicit user confirmation. Issue Closed requires verified sponsor closure date; deliverable Accepted requires date.
8. **Optional automation.** Only after saved app, `read_automation_setup`, `list_app_automations`, `read_app_automation_guide` and actual runner/permissions checks. Offer one weekly shared-runner ChatGPT oversight draft and one separately approved TrialAgents email linked after verified commit, or zero automation. Distinguish enabled vs ready vs verified last run. Never send from app or schedule one Task per app.
9. **Validate.** Reopen in platform and extension; ensure no interruption due to scheduling failures, account access revocation enforced, transient preview recovers, original project/table IDs preserved on app move. Verify runtime log of reviewed changes in platform Logs.

## 1.2.1 executable contract

Use `schema.example.json` for platform-valid fields and `schema_mapping.example.json` for logical mappings. Set every mapped field to `multiple:false`. `project_id` uses `kind:text` and an actual saved engagement UUID; native relationship arrays need an explicit adapter. Choices use `select`; narrative/reference fields use `text`. Bind every mapped field with its current schema version and permitted manifest mode. Original edit/archive versions are retained. Engagement archive fails when any child source or its reference/archive fields cannot be read completely. Denied, short, unknown-total and truncated reads are incomplete, never verified zero.
