# Pipeline Radar 1.0.0 (`life.pipeline-radar`)

Watches competitor pipelines for one or more scopes: new entrants, phase changes, partnerships, discontinuations and readouts, one row per company and asset. Built on the [Bio Radars kit](../../radar-kit/README.md) 1.1.0; scope: [BIO_RADAR.md](../../../../docs/product/app-template-blueprints/apps/BIO_RADAR.md) §2, §3 and §5. **Published:** approved by the owner on 15 November 2026; `templates/catalog-seed.json` approves it on first import (migration 074).

| File | Purpose |
|---|---|
| `radar.json` | The definition: scope fields (indication, mechanism, modality, line, geographies), tracker fields, natural key (company and asset), event kinds (new_entrant, phase_change, partnership, discontinuation, readout, other), digest section ("Phase changes and new entrants"), standard sources (Company pipelines and press releases, Public pipeline summaries, News), default research instruction, weekly cadence (07:00). Generated by `../_tools/make_wave2.py`. |
| `catalog.metadata.json` | Description, tags, whenToUse, whenNotToUse. |
| `demo_data.json` | Fictional scopes, assets, events and runs. |
| `schema.example.json`, `pipeline-radar.preview.html` | Generated by `scripts/build-radar-templates.mjs`. |
| `QA.md` | §5 results. |

Roles: `organizations` (core.v1), `programs` (core.v1, optional, read-only), `pipelineradar.settings`, `.scopes`, `.assets`, `.events` (output, `radar.v1`, one writer), `.runs`. 

Automations (install dialog, both selected): **Pipeline Radar scan + digest** and **Pipeline Radar high-impact alert**, as for every radar. Research may create and update assets (except watched, seen_run_id, dismissed, user_notes, archived), create events and create runs; it never touches scopes or the template.


## Pipeline Radar 2.0.0 (kit 2.0.0, draft)

The same radar rebuilt on the platform kit and the v2 app contract (package 7.3; G2–G8, G11, P3–P5, P9). It waits for the owner's approval (O4) and is not in `templates/catalog-seed.json`; 1.0.0 and 1.0.1 stay published and their packages are unchanged (`archive/1.0.1/`, `archive/1.0.0/`).

- **Screens:** Overview (counts, high-impact events to review, coming dates, what changed in the last run, the last run with its source report one click away), Assets (search, filters and sort on the loaded rows; select, number, date and watched values edit in place; a side panel for details, many fields and adding), Events (To review, All events, Calendar), Scopes (status in place, a side panel to add, edit or remove) and Settings for owners (research template, lookback, language).
- **Removed:** the app's own header, as-of pill and layout gear; the footer and disclaimer bar; the seven banners (messages are platform notices); Automations, version history, return format and "Build now" panels in Setup; the CSV page export; field label editing.
- **Saving:** every change is one `records.save` from a person's click, edit or form with the version shown when the edit started; it saves directly and can be undone. No `records.propose`, no "prepared for review" text.
- **Unchanged for the upgrade:** installer schema, `radar.v1` output contract, both recommended automations and the three helper functions (only their version label differs); `upgradeFrom` lists 1.0.0, 1.0.1. Options `heading`, `layoutProfile` and `demoLabel` are dropped.
