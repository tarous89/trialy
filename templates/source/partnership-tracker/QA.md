## Decisions and limits

- The sanitized frame strips `open` from `<details>` and custom `data-*` attributes, so filters and panel forms are inline sections and the digest and schedule carry ids.
- Records in one review cannot reference each other's new IDs: a new opportunity's first stage is its current stage (stage history records changes), and new partners are saved before the opportunities that use them.
- Document versions are shown as the platform numbers them (a first upload is v0), as in Data Room.
- Local browser runs used the container's Chromium build linked to the path the pinned Playwright 1.51.1 expects; CI installs its own browsers.
- Follow-up reminders are not an install recommendation: recipe emails carry no conditions, and catalog apps cannot ship a summary function, so `status = open` cannot be enforced at install. They are set up in chat as conditioned email actions routed by `owner_member_id`.
- Custom fields need three reviewed steps (table field, app table map and binding, then registration in settings). The layout gear cannot order custom columns, so they follow the layout columns, and saved views can place them anywhere.
- Local browser and design-gate runs used the container's Chromium 1243 linked to the paths that the pinned Playwright 1.51.1 expects.
