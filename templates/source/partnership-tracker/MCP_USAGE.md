# Setup, use and recovery

Read the latest TrialAgents template guidance authoring and usage 1.3.9 (follow nextOffset), design kit and current schema before preparing this app. Use one reviewed catalog preparation with the existing component identity, exact version and digest. This is an internal TrialAgents app: no app-local login or account; the host supplies the official linked watermark. Source must not declare templateConfiguration or templateBindings because AppTemplates injects both. Preserve the six distinct partnering screens with an editorial cream and deep-jade relationship-workbench design with one title and one subline each, full name in sidebar and no in-app logo. Declare native templateLayoutSchema and persist Layout gear changes using the host reviewed customLayout. Create mapped authorized scalar tables in parent-to-child order: programs, organizations, contacts, opportunities, evaluations, meetings, milestones, signals. Exact field schema and logical-to-physical maps follow in dataContract; UUID refs are scalar text fields with multiple:false and archived boolean, not array relations. Use real saved parent receipt UUIDs when linking children, never fictional IDs and never seed demo data. Map writableFields to logical names only within allowed permissions, and bind each physical field with matching manifest schemaVersion, field kind, read/write mode. Support fixed weighted evaluation 35% scientific, 30% strategy, 20% commercial, 15% execution; scores only from a unique complete Reviewed assessment matched to current criteriaVersion and supported by reviewer/date/rationale/HTTPS source. Missing and duplicate reviewed evidence is not zero and never suggests ranking. Stage changes require stageAt and stageNote, documented as a reviewed mutation; Agreement milestones Done require actualAt and evidence. Keep original parent identity/criteria revisions, and block orphan links and dependent archives in the app. Do not assume browser guards are server foreign keys. Use configurable 25-row register pages, 8-row pipeline lane pages and 5-row comparison pages, complete source reads before authoritative metrics and archive eligibility; missing binding, short page, unknown total or denied reads are incomplete. Drafts retain original record version for edit/archive; proposals only count as committed after host receipt. All real inputs/selects/textarea have data-ui-state and stable data-action plus name. Use native review; no fake e-signatures, direct outbound messaging, secret API access, private uploads or external deal room. Save app first; optional ChatGPT/TrialAgents email automations must use the platform shared runner and reviewed action, not per-app tasks or embedded automation settings. Research public nonconfidential partner/company signals only; no proprietary confidential docs sent to websites. Never claim an automation scheduled, email delivered, app installed or backend acceptance without real host evidence. Existing apps must not be silently replaced on retries. Read documentation tasks, examples, limitations and the separate field schema before preparing. Check empty/denied/partial data, 320–1440px, host sandbox with manifest, exact source and database receipts before publication. Require all fields mapped and scalar. Edits and archives use recordId and the original expectedVersion, including zero. Keep proposal drafts until trusted host confirmation; reconcile ambiguous receipts before retrying creates. Partner identity changes require complete reads of evaluations, meetings and milestones and no linked evidence. Program scope and linked company identity cannot silently reinterpret existing evidence. Native field order and visibility applies to editor fields; Additional fields keeps every hidden required input reachable. Do not infer automation setup from this app; use the platform Automations page.
