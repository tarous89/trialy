# Publication Management: MCP setup and recovery

Read the current TrialAgents authoring and usage guidance (1.3.9 or newer) and live design kit. This is Publication Management, an internal TrialAgents app for small biotech and research teams (<50 FTE), based conceptually on iEnvision Datavision planning, review and reporting. NO app auth/accounts or invented TrialAgents logo; use the official host watermark linked to https://platform.trialagents.com. Keep seven distinctive screens and one title plus one subline per screen. The sidebar name "Publication Management" must display in full without an icon. Never create external journal integrations, journal submissions, signatures, patient data or proprietary citation analytics. Before creation, read the available real schema and catalog, then prepare exactly eight authorized scalar tables: projects, manuscripts, authors, reviews, targets, milestones, submissions, reports. Map each logical field to the real lowercase physical key and include it in the manifest with the real table ID, schemaVersion, read/write mode and allowed fields. Use the returned reviewed parent record IDs when linking children. No demo data may enter production. Host injects templateConfiguration and templateBindings: do not prepend them in catalog source. Native layout uses templateLayoutSchema, heading and layoutProfile; gear emits tracker:layout, and changes persist only after prepare_tool_layout review. Forms use data-ui-state on every input, select and textarea and named event.form fields. records.propose is only a proposal; confirm in the host and reconcile original optimistic record versions, never mark saved before receipt. All source reads must prove completeness; handle denied, partial, unknown total and over-budget as missing coverage. Allow all relevant record roles to create/edit/duplicate/archive with protected historical states reset on duplicate, and reachable pagination. Manuscript status Submitted requires existing dated confirmation, current-version author acceptances/disclosures and approved reviews plus source-verified outlet. Published additionally requires actual published event and DOI/date; do not infer from target dates. Store original target/baseline dates immutably, and retain distinct revisions. Author approvals are per draft version, not transferable. Independent database changes are not protected by UI checks: never claim enforced foreign keys. Saved reports are human reviewed, source-identified, versioned and never automatically mailed. ChatGPT drafting and optional public outlet-requirement research happen only through the shared authorized TrialAgents runner; TrialAgents handles any separately approved email. Save the app first; optional automation configuration must not block it. No automation is enabled by this catalog. Do not invent a per-app ChatGPT Task, active subscription or outgoing message. Tests in standalone browser are not live host acceptance; verify the sanitized frame, real QuickJS, manifest, database and catalog discovery before publishing. Keep one main heading/subline, rich editorial styling, responsive 320-1440 layouts. Preserve same app ID on revisions and never create replacement apps after ambiguous receipts. Discover with list_app_templates, read_app_template and the exact current digest, then prepare_app_from_template. Reuse suitable authorized tables. For preview corrections use replacesPreviewId and expectedDigest with the same requestKey; for saved revisions read_project_component and retain its component ID and current version. After native layout confirmation use read_project_component(includeOutput:true). Withdrawn requires a separately recorded dated withdrawal confirmation; historical submission/withdrawal evidence remains protected.

Eight scalar role tables (projects, manuscripts, authors, reviews, targets, milestones, submissions, reports). All fields use lowercase underscore physical keys, with exact logical-to-physical mappings in tableMap. Every scalar has multiple:false, select fields have enumerated options. Required parent IDs are text UUID references to saved authorized records; never use relationships/arrays as IDs. Schema kinds and physical keys: projects: name (text), objective (text), lead (text), archived (boolean); manuscripts: name (text), project_id (text), type (select), status (select), version_label (text), lead (text), target_id (text), target_date (date), initial_target (date), source_url (text), next_action (text), submitted_at (date), published_at (date), doi (text), archived (boolean); authors: name (text), manuscript_id (text), affiliation (text), contribution (text), order (number), invited (boolean), declaration (select), approval (select), approved_version (text), approved_at (date), notes (text), archived (boolean); reviews: name (text), manuscript_id (text), draft_version (text), reviewer (text), feedback_type (select), status (select), due (date), reviewed_at (date), resolved_at (date), approved_at (date), action (text), notes (text), archived (boolean); targets: name (text), kind (select), category (text), scope (text), url (text), verified_at (date), deadline (date), original_deadline (date), alternative (text), notes (text), archived (boolean); milestones: name (text), manuscript_id (text), phase (select), baseline (date), due (date), actual_at (date), owner (text), status (select), notes (text), archived (boolean); submissions: name (text), manuscript_id (text), kind (select), at (date), decision (select), confirmation (text), source_url (text), doi (text), notes (text), archived (boolean); reports: name (text), project_id (text), period (date), cutoff (date), status (select), owner (text), approved_at (date), references (text), body (text), risks (text), archived (boolean). All source URLs, evidence text, notes and report narratives are database text. Date fields are ISO YYYY-MM-DD. Empty optional dates are null; missing required fields must not be coerced into success. Archived is a boolean and requires reviewed update. The app never creates users, passwords, external author accounts or auth tables. Custom frontend-js is app-level access: hiding a tab is never an access grant. The host supplies account, permissions, audit and official linked watermark. Set tableMap to a JSON string {role:{typeId:actual saved UUID,fields:{logicalKey:physical_key},writableFields:[authorized logical keys]}}. Use the eight complete schemas in quickStart with multiple:false; optional blank dates/numbers are null. Create projects/targets first, then manuscripts, then children; use committed receipt UUIDs, including report references. Every readable field must be mapped with current schemaVersion/kind/mode; missing mappings and array values are incomplete. Reads/search cover at most 1200 records per role; use a smaller complete authorized dataset beyond that limit. Evidence checks are application logic, not database-wide integrity constraints.

One H1 and subline per view, seven unique publication workspaces with native tracker:layout. Every transient input/select/textarea has data-ui-state and stable data-action/name. The host injects templateConfiguration and templateBindings exactly once. All database reads use declared typeIds/fields, bounded paging and completeness checks. No count/zero/approval claim on denied/partial/unknown-total data. Tables/boards have reachable pagination; create/edit/duplicate/archive generate exact records.propose operations and carry original expectedVersion through confirmation. Draft input is preserved on errors. Hidden presentation columns remain editable in the details form. Selected project filters are applied before calculating metrics. Submission, publication and report approval require source-backed evidence; statuses are not sent to journals. App-level access is inherited from TrialAgents; custom tabs are not separate security boundaries. Official watermark/link are supplied by host. Platform Automations alone manages optional tasks. Validation and stale-version messages appear inside open forms. Proposals retain drafts until host confirmation/reopen. Native field order/visibility controls registers and editor fields; Additional fields keeps hidden required inputs reachable. Submission history is paged. Copied drafts have no original record identity. Source URLs open through the trusted host link adapter.

Publication records use stable UUIDs and append evidence per draft and submission; the baseline deadline and original source are retained. Changing draft version does not transplant author/review approval. Copies reset version-specific approval and submission/output status, never create new app accounts. Archive checks dependent author, review, milestone, event and reporting roles with complete authorized reads; reviewed reports cannot be archived without returning to Draft. There are no database foreign keys enforced by this source. Config changes are reviewed with expected app version; keep IDs, bindings, audit, grants and disabled automation state across revisions. Saved app remains usable if optional automation or email fails. Reconcile ambiguous save receipts and avoid duplicating proposed writes. Use one requestKey for initial preparation and reconcile the same receipt after ambiguity. Revisions target the same component ID and expectedVersion; do not create replacement apps to recover. Never resubmit a retained create draft after ambiguous confirmation without receipt reconciliation. Standalone preview is fictional only. asOf is a date-comparison reference, not a historical snapshot.

The MCP-returned quickStart contains all eight complete schema/mapping objects, including select options and required/scalar flags. Repository access is not needed to install the template. Keep all bindings and the manifest attached during validation. Never copy the fictional preview records into a live project.
