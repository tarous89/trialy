## Exact data/mutation boundaries

No app-level authentication or permission admin; platform already enforces app, database/field/record and AI scope. Arbitrary frontend-js screens have a **single app-level access boundary** until a proven host section enforcement exists. Hidden sections do not confer restricted access. No external uploads, document signing, GxP validation or patient-level data.

For `records.read`, source requires known `total`, all expected rows for each requested bounded page and all mapped required fields; missing/truncated/denied source produces incomplete analytics rather than zero. Analytics cap is 600 records per role; registers page through source beyond cap with page-local search. Review record updates use `expectedVersion` captured **when editing began**. Delete requests `archived:true` after a complete dependency check, never hard delete. Parent/child integrity remains a host data-constraint responsibility for independent DB edits. No project health inferred from missing updates or from manually entered impact/likelihood scores.

**Date and metric contract:** selected cutoff date is for date-sensitive metrics and report content; current project status/health is a snapshot at the time data is read, not a reconstructed historical health series. Original milestone baseline immutable; slip = `current_date - baseline_date` calendar days; Completed requires actual date/evidence, cancelled is not overdue. Risks High/Critical count only if Open/Mitigating (not Resolved/Accepted). Pending decisions due within seven days exclude past overdue; only owner-reviewed updates count. A missing prior source period does not count as zero. Baseline budgets are single-currency records; no currency translation or aggregation is performed.
