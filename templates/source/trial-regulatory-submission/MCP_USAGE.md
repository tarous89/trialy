# Install and edit through MCP

1. Read the current authoring and usage guidance in full. Discover the exact catalog ID/version/digest through list_app_templates and read_app_template. Read its instructions, documentation, configuration and examples. Reuse the user's existing app when requested, and reuse compatible authorized tables before creating missing schema.
2. Match all seven schemas in schema_mapping.example.json, scalar `multiple:false`, required fields and exact select options. Parent references are scalar text IDs from actual committed receipts. Create submissions, then documents, then linked items/reviews/questions/milestones/reports. Do not invent table/record IDs or import the fictional demo.
3. Supply tableMap role entries `{typeId,fields,writableFields}`, exact logical-to-physical mappings for every field, authorized bindings and the full manifest with actual schema versions and granted read/write modes. Missing optional fields or archive flags are incomplete, not empty. Initialize archived:false; optional blanks are null. Creation requires all mapped fields writable; child edits also require submission status write scope for the atomic version guard.
4. Use prepare_app_from_template with exact discovered ID, version and digest. Keep one requestKey and revise its preview with replacesPreviewId/expectedDigest. Do not redeclare templateConfiguration or templateBindings: AppTemplates.operation injects each once. Return html/css/state separately. Configure heading, tableMap, layoutProfile, approved asOf cutoff and readOnly; no clock guessing. Save only through normal host review; verify the receipt and stable component ID before claiming success.
5. Later edits retain the same app ID, current component version, data, permissions and unrelated settings. Record proposals use recordId and original expectedVersion, including 0. Proposals are not commits. Keep draft/version on rejection or conflict; after confirmation verify receipt and reopen fresh. Never silently retry a stale edit as a create. Child evidence changes include a same-status submission update, atomically pinned to the editor-open parent version. Independently edited Database rows require reconciliation; these app guards are not database-wide constraints.
6. Use native tracker:layout and stable templateLayoutSchema tabs/cols/visible. Review, confirm and reopen the saved layout. Required fields hidden by presentation remain reachable in Additional fields; validation opens them. Do not add an app login, user system or fake logo; the host supplies account, permissions, audit and official watermark.
7. Zero automations is valid. Only after app save and explicit request, follow AUTOMATION_RECIPES.md/current automation tools and the self-contained catalog task contract. No per-app ChatGPT Task, arbitrary email recipients or automatic grants. Metadata does not activate jobs or send mail.

Repository publication, catalog deployment, app save, scheduled execution and actual email delivery are separate outcomes. Verify each before claiming it. The package has no CTIS/FDA submission integration.
