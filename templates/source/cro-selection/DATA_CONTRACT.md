# Scalar data contract

Six normalized data roles: selections{name(required),program,scope,owner,dueDate ISO date,status Draft|RFP open|Evaluation|Decision|Awarded,currency EUR|USD|GBP,archived}; vendors{name(required),services,regions,experience,website text,contact text,lastVerified ISO date,archived}; bids{selectionId,vendorId,status Invited|Received|Declined,fee nullable nonnegative number,passThrough nullable nonnegative number,startupWeeks nullable number,assumptions,clarification,clarificationDue,submittedAt,archived}; criteria{selectionId,name,category Scientific|Operations|Quality|Technology|Commercial,weight percentage 0..100,mandatory boolean,minimum 1..5,owner,archived}; ratings{selectionId,vendorId,criterionId,reviewer,score 1..5,evidence,rationale,archived}; decisions{selectionId,vendorId,status Draft|Approved,rationale,approver,approvedAt,nextStep,archived}. Normalize vendors globally, bids/criteria/ratings/decisions per selection. Read only authorized fields using tableMap and templateBindings. Score one criterion as average of recorded ratings (not imputed) then provisional normalized score=sum(weight*meanRating/5)/sum(scoredWeights)*100. Coverage=sum(scoredWeights)/sum(allWeights). Gate approval on Received bid, 100% defined total weight, complete ratings and each mandatory mean>=minimum. Price is never part of composite rating unless explicitly rated as Commercial criterion. Cost and pass-through are separate and a single owner-chosen currency. Never automatically award. Demo records fictional and never committed. Auth and privacy always inherited from TrialAgents. All fields are scalar: set multiple:false explicitly. Use text for URLs, evidence, multiline notes and references containing saved record UUIDs; number for fee/passThrough/startupWeeks/weight/minimum/score; date for dueDate/lastVerified/clarificationDue/submittedAt/approvedAt; boolean for mandatory/archived; select for status/currency/category with the values listed above. Map every logical camelCase key to its lowercase snake_case database key (selectionId→selection_id, vendorId→vendor_id, criterionId→criterion_id, passThrough→pass_through, startupWeeks→startup_weeks, dueDate→due_date, lastVerified→last_verified, clarificationDue→clarification_due, submittedAt→submitted_at, approvedAt→approved_at, nextStep→next_step). All other keys are already valid. Bind every listed field; partial/multiple schemas require explicit repair before use. Amounts are scalar numbers in the selected currency, missing values null. Do not use multi-value relationship fields. Save parent selections/vendors/criteria first and use their receipt IDs in dependent records. Reuse verified records; never commit fictional demo data.
