# Optional automation

Only if requested: prepare a weekly authorized internal sourcing review through the shared ChatGPT runner, or send a separate fixed notification when a human-reviewed award enters Approved. Zero automations is valid.

Before preparation read the current `read_app_automation_guide`, and verify saved app ID, current sourcing project, accessible table IDs, approved source scope and any ongoing write grant. Dedupe by app+project+evidence cutoff+run reference. Never send supplier emails or retrieve restricted provider bids outside the host. Read read_automation_setup, list_app_automations and read_app_automation before configuration. Use stable authoringKey sponsor_rfp_review_v1 with prepare_app_monitoring and the shared owner/workspace runner. Suggested Monday 09:00 in the owner-confirmed IANA timezone, approved anchor/expiry/scopes and 7-day lookback, coalescing missed windows. Prefer supported Work chat, high reasoning and latest most capable available model; report actual host settings separately. No per-app ChatGPT Task. Preserve disabled state, hidden settings and grants on edits; archive suspends, restore/copy does not activate; outcomes belong in Logs. Setup failure leaves manual use available. Use inheritAppAccess:true and current app-bound read fields with no ongoing write scope for this read-only objective. Complete results report the full project scope even with no changes. Use no_update only with complete coverage and an owner-approved quiet policy; never silence incomplete evidence. A denied, expired or partial read stops processing without advancing coverage. The trigger is a dispatch target, not a promised completion time.

Return an internal narrative draft in the current authorized conversation for one-time drafting; for recurring work, return the narrative in the permission-checked monitoring run result/history with exact source record IDs, dates, gaps and reviewer disagreements. This eight-table package has no reports table: never invent a report destination or save prose as an approval. A user may separately approve a Draft award memo in awards.rationale/caveats with a real project and invitation; this is not a winner recommendation or Approved decision. Partial/blocked results never advance coverage or trigger completion email. No automatic writes are included in the suggested research workflow. Manual tracking and one-time drafting work without any automation. If explicitly requested, use a separate single-step TrialAgents email action (authoringKey sponsor_rfp_decision_email_v1) triggered by awards.status entering Approved, rechecking archived is not true. Subject: Sponsor RFP decision recorded. Body: Open https://platform.trialagents.com to review your authorized sourcing decision. Use fixed text, registered owner and specifically selected currently authorized teammates only. No second schedule, research completion email or supplier mail. Delivery failure does not rerun research. No standalone automation Delete action.

Read the current authorized Sponsor RFP Management app and its linked project, requirement, bid, reviewer and award records (not other sponsors). Summarize the RFP scope, bid completeness, mandatory gaps, documented score criteria, reviewer disagreements, outstanding clarifications, due dates, and explicit approval conditions. Draft an internal evaluation brief citing exact saved record IDs; label uncertain or unavailable evidence. Do not rank on missing answers, select a CRO, email vendors, activate monitoring, or write without a reviewed proposal. If a requested recurring monitor is authorized, only configure it through supported TrialAgents app monitoring/actions after saved app and setup checks; otherwise no task is created.

The typed notification example in automation.example.json is also embedded in catalog quickStart. Replace placeholders with reviewed real IDs, field names, appVersion, expiry and selected registered users. No job or email is created by installing or rendering this template. Full weekly narrative output is completed even with zero changes; partial evidence is blocked/partial, never no_update. Shared host tests cover duplicate runs, expiry/revocation, missed work and notification cancellation/coalescing. Actual unattended execution and email delivery require separate live receipts.
