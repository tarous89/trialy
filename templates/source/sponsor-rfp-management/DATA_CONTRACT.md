Source type: `records.read({typeId,offset,limit})` via currently granted bindings and manifest, with `rows`, integer `total`, row IDs and versions. Each role requires complete authorized read for approval; unavailable, unknown total, missing required field, duplicate row or exhausted read budget is incomplete (never zero). UI refs are scalar committed record UUIDs, not arrays. Invites reference projects/providers; requirements reference projects; responses/reviews reference invite+requirement of same project; awards reference invite of same project. Parent archives blocked by verified live dependent children. Manual supplier bid data is sponsor-private and should never be copied to shared provider organization fields. No server-level FK constraint is created by UI validation: independent database writes still need host policy and reconciliation. All fields must be mapped, including optional evidence and archived. Required row fields and mandatory must be returned; arrays/objects are invalid. Optional empty dates/numbers/references are null, text may be empty, and new archived flags are false. tableMap is JSON {role:{typeId:real UUID,fields:{logicalKey:physical_key},writableFields:[logical keys]}}. Use real schemaVersion/kind/mode in the manifest. Every child write requires projects.status write permission for atomic optimistic concurrency. Maximum 960 records per role (96 reads); incomplete coverage blocks writes. Requirements.mandatory must be an explicit boolean; null is unknown and blocks complete coverage.

All columns use multiple:false. The accompanying JSON supplies the exact real create_type field definitions. Requirements.mandatory must be explicitly true or false and every new archived flag is false. Data relationships are committed scalar UUIDs, never demo strings or objects.
