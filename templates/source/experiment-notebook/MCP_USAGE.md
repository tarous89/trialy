# MCP setup and use

Read current authoring and usage guidance completely (1.3.9 at creation), design kit, and this exact version/digest before editing. Experiment Notebook is for small biotech/nonclinical research teams, inspired by eLabFTW, not an installed eLabFTW integration. Internal TrialAgents identity and official linked platform watermark only: no in-app login, accounts, OAuth, credential storage, fabricated logos or remote assets. Preserve six specialized screens and the scientific paper-like layout. Create or reuse seven database roles: projects, experiments, protocols, observations, measurements, interpretations, reports. Use valid TrialAgents types text/number/date/boolean/select; strings for file URL and detailed method, NOT unsupported url/longtext schema kinds. Map logical camelCase fields to actual snake_case; real table UUIDs and schemaVersion/field manifests are mandatory. Bind only authorized fields; do not derive permissions from visible tabs. Use strong project-bound permission scopes (experiment and result links) and preserve method/source history. Screen section keys are presentation only, not separate security boundaries. Never seed demo data. Capture only nonclinical lab work: no patients, subject identifiers, human specimens, medical or clinical records. Never claim GxP validation, compliant signatures, automated instrument uploads, or full ELN functionality. Use stable experiment codes, dated observations, exact method version, individual source-backed replicates with units and controls. Protocol revisions already referenced by an experiment are immutable: Duplicate creates a new draft version; no rewriting historical protocol. Plot valid numeric readings within one selected analyte/unit; show sample n and sample SD only when n>=2, never infer p-values, significance, conversions or error bars. Incomplete or permission-denied data suppresses derived results. All edits, duplicates and soft Delete are reviewed records.propose with exact fields and existing expectedVersion; do not imply a proposed edit was saved. The native gear opens tracker:layout via templateLayoutSchema, reviewed customLayout/expected app version updates; don't create a fake in-app layout manager. Save the app first, verify app ID and reopen; never create duplicate saved apps on retry. Do not add per-app automation settings pages. Optional ChatGPT periodic internal scientific interpretation is only recommended metadata: after saving, read_automation_setup/list_app_automations/read_app_automation_guide and prepare_app_monitoring if specifically approved, using one shared runner with owner/workspace subscription and stable authoringKey; manual processing remains valid. If an approved separate internal email is required, use TrialAgents prepare_app_action after verified authorized report status transition (Draft → Reviewed), recipients owner/approved existing team only, with dedupe, no independent schedule for processing-to-email; ChatGPT must never send email. No mandatory external API, connector, export or instrument system. Test source with manifest and sanitized host, 390/768/1440 widths, read-denied and partial cases, conflicts, report approval, method version immutability and duplicates. Preserve source IDs, layout, access, archive and disabled automations on revisions. All controls use data-ui-state. Empty start: create a research project from the overview, then a protocol, then an experiment. Keep record drafts after proposal for cancellation/retry. After confirmed receipt reopen or cancel the draft. All critical sources must be complete before writes. Return Reviewed interpretations/reports to Draft and Completed experiments to Needs review before modifying supporting evidence; this is an app guard, not a database foreign-key or immutable-history guarantee.

Open within existing TrialAgents account/workspace. No additional login or users, and official watermark already links to https://platform.trialagents.com.

Check latest authoring/usage guidance and template digest; read existing authorized schemas before creating any records.

Create or reuse nonclinical projects and exact versioned protocols, then linked experiments; map 7 roles using actual table UUIDs, field keys and manifests.

Start by entering objectives, hypotheses, approved method versions and run conditions; only authorized measurement and dated observation records count.

Plot source-backed numeric replicates with explicit matching unit; record separate scientific interpretation with limitations.

Draft a human-reviewed project memo in ChatGPT if wanted; use platform Automations only after separate authorization.

Seven persistent role tables with stable UUID relationships: projects, experiments(projectId,protocolId), protocols(versionLabel), observations(experimentId), measurements(experimentId,analyte,condition,timePoint,replicate,value,unit,control,sourceRef), interpretations(experimentId), reports(projectId). No external or human subject information. Demo data is wholly local and fictional. Each role requires a real bound typeId and approved table-level manifest; logical camelCase keys map to actual snake_case column keys. No copied protocol text retroactively overwrites old source. Raw laboratory files are *references* only, not stored or uploaded by frontend-js. Fetch each role in <=7 pages of <=100 records; suppress derived metrics on partial/denied result, never count a single page as total. Archive sets authorized archived:true with reviewed update; not hard deletion. Fields remain scalar except explicit text lists in batch references. Optional project segregation requires backend permissions; custom screens have app-level access only. All fields are scalar multiple:false. Optional empty values are null; required fields cannot be empty. Physical keys and exact select options are specified in the role schemas below. Relation text stores saved record UUIDs, not labels or arrays. Create parents first and substitute committed receipt IDs. Table map is a JSON string keyed by role: {typeId:actual UUID,fields:{logicalName:physical_key},writableFields:[authorized logical names]}. Bind all readable physical keys and manifest fields with current schemaVersion/kind/mode. Missing mappings, unknown totals, arrays and truncated reads are incomplete, not zero. Keep different recorded time points in separate descriptive groups even when analyte, unit and condition match.

Pin exact app/template version and digest, use one requestKey for first save, verify saved app ID/version and reopen. Revise existing app only with expectedVersion; reuse the same request key after an ambiguous response and reconcile transaction receipt; never create new app to recover. Source references and method versions remain stable. Permission revocation and stale versions prevent edits. Layout revisions update only heading/order/visibility. App archive suspends linked automations; restore does not implicitly reenable them; disabled automation edits preserve disabled state. Initial app and records load without any automation running. No GxP signature or immutable audit validation claim.
