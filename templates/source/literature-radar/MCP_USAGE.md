# MCP setup and recovery

Read the entire current TrialAgents template authoring and usage guidance using read_app_template_guidance until nextOffset is exhausted. Read app design, list_app_templates, read_app_template and pin exact digest/version before preparing. This is an internal app; use the existing TrialAgents account, DB grants, official host watermark linking to https://platform.trialagents.com. No app login, user table or independently managed email. Preserve exactly six distinct screens and one page heading plus one concise subline, no global taglines. Read/validate actual authorized schemas and configure role mappings with real saved typeIds and lowercase keys for topics, publications, matches, screenings, findings, reports and runs. Reference fields are scalar text keys storing real record IDs; status and date scalar, URL and narrative text. Include every bound field in authorized manifest with live type schema versions and read/write permissions, never copy fictional UUIDs/DOIs into production. DOI canonicalization strips resolver/doi prefix and normalizes case; PMID is numeric; do not create duplicate DOI/PMID across projects. Separate publisher metadata, topic relevance, human screening judgments and ChatGPT interpretations. Do not infer patient data, study population eligibility, paper impact, unobserved connections, citation graph, or full-text access. Only real bibliographic evidence with verified source and date may be saved. Never silently alter past topic scope decisions: bump scopeVersion for changed questions/keywords/rubrics; retain prior scope and reviewer audit history. Included and Excluded decisions must have reviewer, date, evidence rationale and a matching decision. Report Reviewed requires verified included citation record IDs in same topic, reviewer/cutoff and limitations; all ChatGPT drafts remain Draft until human reviewed. Custom frontend-js access is app-level; hiding screens or filtering topic is not authorization. Use native gear tracker:layout and declarative templateLayoutSchema with reviewed prepare_tool_layout. Screen/field drag changes only presentation data and uses expectedVersion; preserve component ID/permissions/source. Use unique data-action and data-ui-state forms. Every write is an exact records.propose requiring separate host review/receipt; duplicate drafts reset DOI/PMID or reviewer status; Delete proposes archival with archived=true, never hard-delete. On ambiguous response retry with same requestKey/reconcile receipts, never create a duplicate app/record or overwrite stale revisions. Automation is OPTIONAL. Save and reopen a usable app before automation setup. Quietly check read_automation_setup, read_app_automation_guide and list_app_automations; for accepted monitored discovery use prepare_app_monitoring via shared ChatGPT owner/workspace runner, optionally separately approved completion email via prepare_app_action. No ChatGPT task per app, no ChatGPT email sending or direct email from generated source. Stable authoringKey, scoped access, explicit source/coverage/dedup, approved save receipts; newSavedCount>0 triggers completion email only if separately approved; 0 new saves permits no_update only with complete coverage and approved quiet policy; otherwise record the required outcome. Respect disabled/archive states, current permissions, recipient limits, expiry. If no task capability or user declines use manual ChatGPT instructions; failure of setup never blocks app loading or record use. No external paid API, scraper or unlicensed full text. Host confirmations and actual scheduled runs must be tested before claiming deployment. Authoring 1.3.9 publication blockers: never declare templateConfiguration or templateBindings in catalog source. Use actual host-prepended config/bindings; no mock form field events. Mark every input/select/textarea with data-ui-state, stable action and name. Preserve form drafts and original record versions on conflict. Do not claim complete totals from unavailable, unknown-total, short-page, missing fields or >1200-row reads; paginate screens and comparison views. No paper approval or final report from incomplete evidence. Only official host watermark branding; keep complete Literature Radar name without sidebar logo. Native layout changes reflect stored order and visibility. Host end-to-end acceptance remains required.

Seven optional physical tables: topics (scopeVersion, keywords, owners), publications (canonical DOI/PMID, firstSeenAt, publisher metadata and verifiedAt), matches (topicId/publicationId/scopeVersion), screenings (topicId/publicationId/stage/decision/reviewer/evidence), findings (reviewed source claims), reports (citations/limitations), runs (source coverage, savedCount, outcome). All relationships are exact, authorized saved record IDs. Multiple topics can reference the same global publication record; do not clone master publication metadata. Authoritative data are only saved, committed records via manifest+grants. Unsaved form input and layout selection live in transient state; demo data are fictional and never seeded. The 1200-row-per-role guarded read budget requires indexed/backend paging beyond that range; partial reads are never authoritative. Record-level access and section isolation remain backend responsibilities; custom source is app-level access only. No publication or patient-level full text is ingested. Required physical schema (all fields scalar/multiple:false; real UUID references stored as text; source URLs and reports stored as text): topics -> name:text, question:text, keywords:text, exclude_terms:text, source_scope:text, start_year:number, owner:text, rubric:text, scope_version:number, last_checked:date, active:boolean, archived:boolean; publications -> name:text, authors:text, journal:text, published_at:date, doi:text, pmid:text, url:text, verified_at:date, first_seen_at:date, source_label:text, abstract:text, archived:boolean; matches -> name:text, topic_id:text, publication_id:text, relevance:select{Unassessed|High|Medium|Low}, rationale:text, discovered_at:date, scope_version:number, archived:boolean; screenings -> name:text, topic_id:text, publication_id:text, stage:select{New|Reading|Reviewed|Included|Excluded}, decision:select{Uncertain|Include|Exclude}, reviewer:text, due:date, reviewed_at:date, priority:select{High|Medium|Low}, rationale:text, notes:text, archived:boolean; findings -> name:text, topic_id:text, publication_id:text, claim:text, limitations:text, source:text, reviewer:text, reviewed_at:date, status:select{Draft|Reviewed}, archived:boolean; reports -> name:text, topic_id:text, cutoff:date, status:select{Draft|Reviewed}, author:text, reviewed_at:date, references:text, body:text, limitations:text, archived:boolean; runs -> name:text, topic_id:text, status:select{completed|no_update|partial|failed}, started_at:date, completed_at:date, found_count:number, saved_count:number, summary:text, source:text, archived:boolean. Missing or unauthorized fields => incomplete data, not zero. Set tableMap to a JSON string {role:{typeId:actual saved UUID,fields:{logicalKey:physical_key},writableFields:[authorized logical keys]}}. Use the complete scalar schemas in quickStart; optional blank dates/numbers are null. Create topics/publications first, use committed receipt UUIDs in child references, then findings/reports/runs. Bind every readable field with current schemaVersion/kind/mode. All fields must be mapped; arrays and inaccessible fields are incomplete. Never seed fictional data.

App is saved once under a stable ID. Exact version/digest for catalog, same component ID and requestKey/expectedVersion for corrections, no duplicate apps on retries. Every proposal needs human confirmation; stale optimistic versions and denied writes fail safely. Delete means reviewed archived:true. Shared publication cannot be archived while linked matches/screenings/findings exist. Topic scope changes bump version and require revalidation of matching; old decisions are not rewritten. Optional automation definitions are managed in TrialAgents, stable authoringKeys with separate approval; disable state survives edits, archive suspends, restore does not auto-restart; task failure never prevents app from opening. Source changes never create identity/permission grants. Archive confirmation and edit record expectedVersion are captured when the drawer opens and never upgraded at submit. Dependent record completeness is required for archive; changed verified evidence is blocked or requires re-review. Revisions create a new catalog semver rather than overwriting existing catalog entries.

Create parents first and use receipt UUIDs in all child references and report references. Never infer persisted identity from a display name. Configure all seven roles; partial/denied/missing/array data cannot establish completeness. All fields are scalar; optional empty dates/numbers are null. Read/search coverage is bounded to 1200 per role. For larger datasets use a narrower authorized dataset or a separately designed backend paging implementation.

Only the host injects templateConfiguration/templateBindings. Keep the manifest attached. Each transient control has data-ui-state and a named action; form submission uses event.form. Existing edits/archives carry their original version and recordId. Proposals remain unsaved drafts until a trusted receipt; on ambiguity reconcile the original receipt before repeating a create. Close discards local drafts. Errors remain visible inside the editor. Native layout changes presentation only; all form fields remain reachable, ordered with configured fields first.

A new scope must not reinterpret prior screening/findings. Once dependent evidence exists, duplicate the topic for a changed scope. Reviewed reports must return to Draft before modifying their supporting reviewed findings. These guards are application logic, not database-wide foreign keys or protection against independent table edits. Reconcile those edits before relying on approvals. The asOf value is a date comparison reference, not a historical snapshot.
