# Inventory Management 1.0.2

Six-screen internal TrialAgents app for nonhuman lab supplies: overview, inventory/lots, stock movements, storage locations, purchase requests and usage forecasts. No app-level authentication, supplier ordering or automatic background services. Host watermark uses the official linked TrialAgents logo.

## Canonical package

`inventory.source.js`, `inventory.css`, `catalog.metadata.json`, `schema.example.json`, `layout.schema.json` and fictional `demo_data.json` are canonical. From repository root run `node scripts/build-inventory-template.mjs`; it deterministically builds `templates/apps/life.inventory-management-1.0.2.json` and `inventory.preview.html`. `npm run build` checks generated bytes with `--check`. The preview is local fictional data, not a saved app. Do not run old uploaded patch/release scripts.

MCP discovery/read exposes all setup instructions, exact scalar schemas, mappings, lifecycle, access boundaries and optional automation recipes in catalog documentation. Use the catalog's exact version/digest and one stable creation request key. See INSTALLATION_AND_MCP.md and AUTOMATION_RECIPES.md. Native `tracker:layout` settings use the literal layout schema and versioned platform review.

## Stock correctness

Dates are business dates with **end-of-day** balances: all effects on a date are summed before validating that day's lot/location closing balance. UUID order never determines availability. This does not model intraday custody.

Each lot has a required scalar numeric `stock_revision`, initialized to 0 and mapped as writable. The app hides/manages this counter. A movement proposal contains an expected-version counter increment and an immutable movement create, in one reviewed atomic batch. Competing proposals against the same lot version cannot both commit. Failed batches roll back both changes; confirming the same preview/digest reconciles the existing receipt. Never split the batch, drop the version guard or blindly create a second proposal after an ambiguous save. Drafts remain available when review is cancelled or rejected.

Independent direct Database editing does not enforce this application's ledger invariants. Restrict ordinary movement posting to this reviewed app workflow. Read/validate preexisting data before reuse; never seed fictional data into a real workspace. The 800-row-per-role ceiling is explicit: totals/posting are withheld above it, requiring an authorized server aggregate for larger installations.

No optional automation is activated by installing the template. Research/email definitions, live host connection and delivered emails are separate outcomes, never prerequisites for inventory use.
