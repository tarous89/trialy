# Optional automations

No automation is the default. Save the app and verify receipt/app ID first. Read read_automation_setup, list_app_automations and read_app_automation_guide. Reuse stable identities and existing shared runner; never create a per-app ChatGPT Task. Definitions remain listed and editable when disabled. Editing preserves disabled state; archive suspends runs and restore/copy never resumes them. Automation outages cannot block this app or clear drafts.

## Weekly public capability evidence

With owner approval use weekly Europe/Berlin and authoringKey life.cro-site-feasibility.weekly-site-capability.v1. Use the exact prompt in catalog documentation.tasks.promptExample. Read complete authorized institution profiles and current project criteria. Research official public institution sites and registries, record URLs and observed/publication dates, and reconcile existing IDs plus official name/city/country/website. Never copy sponsor-private answers into the reusable master or infer patient counts/enrollment.

Output proposed site changes only; do not create an unspecified report table. Dedupe by canonical site identity, source revision/date and run receipt. Writes require exact trusted review every time unless an explicit unexpired scoped grant covers those fields/operations. Preserve scope, expiry and receipts on retries. Missing authority leaves a pending proposal, not a completed save. No_update requires complete coverage and an owner-approved quiet policy. Partial/denied sources are incomplete, not silent success. Do not approve responses, rank incomplete evidence or select sites.

## Independent internal handoff notification

Use authoringKey life.cro-site-feasibility.email.candidate-proposed.v1, separately approved through prepare_app_action. Trigger on a real committed candidates.stage transition into Proposed using the discovered actual field key and current typed trigger schema. This is distinct from public site enrichment; a research run does not imply an approved shortlist. No second completion email for the same transition.

Owner is the default recipient. Add only explicitly selected registered team members with current app/data access; investigator/sponsor contact fields never authorize recipients. Suggested fixed subject: “Site feasibility review requested”. Fixed body: “A site candidate is ready for internal review. Open the linked app to review the evidence and next steps.” Use the platform-supported app link and only placeholders supported by the current guide, never invented study-name or timestamp interpolation.

Pending/failed writes, duplicate or reversed transitions, archived apps and revoked recipient access must not send. Platform coalescing and delivery limits apply. Failed delivery does not rerun research or change approved records. Keep outcome details in Logs, not another app dashboard. An enabled definition is not proof of runner readiness or actual delivery; verify those separately.
